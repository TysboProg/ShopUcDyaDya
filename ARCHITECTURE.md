# Архитектурный план ShopUcDyaDya

## Цель проекта

ShopUcDyaDya — это UC-магазин, ориентированный на Telegram.

Основной пользовательский интерфейс находится в Telegram. Веб-приложение Telegram используется только там, где веб-интерфейс удобнее: выбор товара, форма заказа, ввод промокода и процесс оплаты. Взаимодействие с ботами, действия администратора, уведомления и поддержка остаются в Aiogram.

## Архитектура высокого уровня

Проект представляет собой единое бэкэнд-приложение с двумя публичными точками входа:

- Приложение FastAPI для страниц веб-приложения Telegram, обратных вызовов платежей и внутренних HTTP-маршрутов.

- Бот Aiogram для пользовательских сценариев Telegram, команд администратора и уведомлений.

Обе точки входа должны использовать одни и те же доменные сервисы. Бизнес-правила не должны дублироваться между обработчиками HTTP и обработчиками Telegram.


```текст
Пользователь Telegram
-> бот aiogram

-> открывает веб-приложение Telegram

-> HTML/HTMX страницы FastAPI

-> Конечные точки заказа/оплаты FastAPI

-> база данных

-> уведомление aiogram пользователю/администратору
```

## Обязанности

### FastAPI

FastAPI отвечает за:

- Рендеринг страниц веб-приложения Telegram с использованием HTML-шаблонов.

- Предоставление конечных точек HTMX для динамических фрагментов страниц.

- Предоставление статических ресурсов при необходимости.

- Валидацию `initData` веб-приложения Telegram.

- Создание заказов на основе данных, отправленных через веб-приложение.

- Применение промокодов при оформлении заказа.

- Запуск процесса оплаты.

- Получение обратных вызовов/вебхуков платежного провайдера.

- Обновление статуса заказа и платежа.

- Предоставление конечных точек проверки работоспособности и утилит разработки.

FastAPI не должен содержать логику команд бота Telegram.


### Aiogram

Aiogram отвечает за:

- `/start` и регистрацию пользователя.

- Главное меню Telegram.

- Отправку кнопки WebApp.

- Создание промокода администратором.

- Поиск заказов администратором и оперативные команды.

- Уведомления пользователя о статусе заказа.

- Уведомления администратора о оплаченных или проблемных заказах.

- Команды поддержки и простые сценарии FAQ.

Обработчики Aiogram должны быть простыми. Они должны вызывать сервисы из модулей домена.

### Telegram WebApp

WebApp отвечает за:

- Выбор продукта/пакета UC.

- Сбор необходимых данных заказа, например, ID игрока/аккаунта.

- Ввод промокода.

- Отображение рассчитанной общей цены.

- Начало платежа.

- Отображение состояния успеха, ожидания или неудачи.

WebApp должен быть оптимизирован для использования Telegram на мобильных устройствах и не должен превращаться в полноценную панель администратора.


### Ngrok

Ngrok используется для локальной разработки:

- URL веб-приложения Telegram по протоколу HTTPS.

- URL веб-хука бота, если он используется.

- URL обратного вызова платежного провайдера.

Для продакшена Ngrok следует заменить стабильным доменом, VPS, обратным прокси и сертификатом HTTPS.

## Модули домена

### Пользователи

Хранит данные пользователей Telegram и облегченные данные клиентов.

Основные поля:

- Идентификатор пользователя Telegram.

- Имя пользователя.

- Имя.

- Фамилия.
- Код языка.
- Роль: клиент, администратор.

- Временные метки создания/обновления.

Основные действия сервиса:

- Получить или создать пользователя Telegram.

- Проверить права администратора.

- Обновить данные профиля из Telegram.

### Товары

Хранит пакеты UC и публичный каталог магазина.

Основные поля:

- Название товара.

- Количество UC.

- Базовая цена.

- Валюта.

- Статус активности/неактивности.

- Порядок сортировки.

Основные действия сервиса:

- Список активных товаров.

- Получение товара по ID.

- Включение/отключение товара.

- Обновление цены.

### Промокоды

Сохраняет промокоды, созданные администраторами.

Основные поля:

- Код.

- Поведение в отношении скидки или суммы UC.

- Статус: активный, использованный, просроченный, отключенный.

- Дата истечения срока действия.

- Лимиты использования.

- Использован пользователем/заказом.

Основные действия сервиса:

- Создание промокода.

- Проверка промокода.

- Применение промокода к черновику заказа.

- Отметка промокода как использованного.

- Истечение срока действия устаревших промокодов.

Создание промокодов должно быть сначала доступно через команды администратора aiogram.

### Заказы

Сохраняет покупки, созданные из веб-приложения.

Основные поля:

- ID пользователя.

- ID товара.

- ID игрока/аккаунта.

- Базовая сумма.

- Сумма скидки.

- Итоговая сумма.

- Валюта.

- Статус: черновик, ожидание оплаты, оплачено, обработка, завершено, отменено, не выполнено.

- Примененный ID промокода.

Основные действия сервиса:

- Создать черновик заказа.

- Рассчитать окончательную цену.

- Прикрепить промокод.

- Переместить заказ в режим ожидания оплаты.

- Отметить заказ как оплаченный.

- Отметить заказ как завершенный.
